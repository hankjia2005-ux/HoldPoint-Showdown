# 分支与发布策略

## 永久分支

| 分支 | 用途 | 合入条件 |
|---|---|---|
| `main` | 可演示、可打包的稳定版本 | 里程碑验收通过，无 S0/S1 问题 |
| `develop` | 下一版本集成 | 功能分支完成自测和评审 |

## 短期分支

- `codex/feature-*`：玩法、系统或工具开发。
- `codex/fix-*`：Bug 修复。
- `codex/art-*`：大型美术批次，便于独立检查导入设置和体积。
- `codex/docs-*`：策划、测试和作品集文档。

资源类型不使用永久分支。代码、美术和音频需要在同一功能中共同验证，长期拆分会让 Unity 场景、Prefab 和 `.meta` 文件频繁冲突。

## 发布标签

- `v0.1.0-prototype`：移动、射击与联机技术验证。
- `v0.2.0-core-loop`：三阶段和物资闭环。
- `v0.3.0-vertical-slice`：首个完整展示版本。

## 合并规则

- 功能分支使用非快进合并或 Pull Request squash。
- `main` 只接受来自 `develop` 的里程碑合并或紧急修复。
- Unity 场景冲突优先由实际负责该场景的人在编辑器内处理。
- 合并后必须重新打开项目，检查丢失脚本、Prefab override 和构建场景列表。
