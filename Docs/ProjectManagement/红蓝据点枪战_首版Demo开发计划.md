# 《红蓝据点枪战》首版 Demo 开发计划

> 版本：Portfolio Vertical Slice V0.1  
> 制定日期：2026-11-02  
> 制作方式：个人开发者 + AI 协作  
> Unity：6000.6.6f1，URP 3D 项目  
> 基准工期：8 周，每周约 20～25 小时；若全职投入可压缩为 5～6 周

## 1. 首版目标

首版不是一次性实现完整商业版本，而是做出一个可玩、可录屏、可面试讲解、技术链路完整的垂直切片。

最终交付应证明四件事：

1. 三阶段规则能够形成“发育—偷家—决战”的清晰节奏。
2. 2V2 下共享箱、物资争夺、入侵提示能够带来团队决策。
3. 单机 AI 和联机房间均能完整打完一局。
4. 项目具有数据驱动、网络同步、AI 状态机、移动端适配和性能优化等可写入简历的技术内容。

## 2. 范围决策

### 2.1 首版必须完成（P0）

- 第三人称视角，单张对称卡通城镇地图。
- 2V2 为唯一正式人数档位。
- 单机模式：1 名玩家 + 3 名 AI，能够完整结束一局。
- 自定义联机房间：创建房间、加入码加入；真人不足时可由 AI 补位。
- 完整三阶段：00:00～03:00、03:00～05:00、05:00～12:00。
- 红蓝基地、保护罩、公共城镇、可进入建筑、共享物资箱。
- 移动、跳跃、下蹲、开门、自动拾取、背包、存取物资、瞄准、射击、换弹、治疗。
- 4 档武器：手枪、冲锋枪、步枪、连发霰弹枪。
- 子弹、医疗包、护甲三类物资。
- 死亡掉落、阶段复活规则、两命淘汰、胜负和平局结算。
- 基地入侵、箱子被抢、阶段切换、击杀和队友状态 UI。
- Windows 可执行版本、Android APK、90～120 秒作品集演示视频素材。

### 2.2 有余力再做（P1）

- 快速加入房间列表。
- 4V4 压力测试模式。
- 小地图、观战镜头、简单战绩面板。
- 更丰富的建筑组合、角色外观和枪口特效。

### 2.3 首版明确不做（P2）

- 3V3 / 4V4 / 5V5 正式匹配队列。
- 公共匹配、排位、赛季、成长、成就、商城、社交、语音。
- 专用服务器、断线重连、主机迁移、复杂反作弊。
- TapTap 正式发布流程、支付、实名认证、隐私合规接入。
- 黑夜、天气、多地图、多角色数值差异。

## 3. 关键设计假设

- 视角采用第三人称。2 头身角色需要被看见，同时更适合轻量移动端射击。
- 先做 Windows 键鼠版以提高迭代效率，核心玩法稳定后再加移动双摇杆和触控按钮。
- 正常对局使用策划案中的 12 分钟上限；开发环境提供 3 分钟快速规则配置，用于高频测试。
- 首版联机使用玩家主机权威的 Listen Server。房主负责阶段、伤害、物资、AI 和胜负裁定。
- 作品集重视“完成度与可说明性”，不以在线人数或商业化系统数量衡量。

## 4. 技术方案

### 4.1 推荐技术栈

- 引擎：Unity 6000.6.6f1。
- 渲染：Universal Render Pipeline（URP）。
- 输入：Unity Input System，一套 Action Map 同时映射键鼠和移动端。
- 联机：Netcode for GameObjects。
- 房间与公网连接：Unity Multiplayer Services 的 Sessions + Relay。
- 导航：Unity NavMesh，AI 只在主机运行。
- 配置：ScriptableObject 管理武器、物资、阶段、地图刷新和 AI 参数。
- UI：uGUI，首版优先稳定和移动端适配。
- 版本管理：Git；大体积美术源文件使用 Git LFS。

采用 Sessions + Relay 是因为 Unity 6 官方当前推荐 Multiplayer Services SDK 统一管理 Lobby、Relay 和 Matchmaker。首版只使用房间与 Relay，不引入高级 Matchmaker。

### 4.2 权威边界

| 内容 | 裁定方 | 客户端职责 |
|---|---|---|
| 阶段计时、阶段切换、胜负 | 主机 | 显示倒计时和提示 |
| 生命、护甲、伤害、死亡 | 主机 | 请求开火、表现受击 |
| 物资生成、拾取、掉落 | 主机 | 发起交互、播放表现 |
| 背包与共享箱 | 主机 | 打开界面、提交存取请求 |
| AI 决策与移动 | 主机 | 接收并表现同步状态 |
| 玩家移动 | 所有者输入，主机校验 | 本地即时响应 |

### 4.3 核心代码模块

- `GameFlow`：房间状态、准备、三阶段状态机、计时、结算。
- `Player`：移动、相机、输入、阵营、生命、护甲、死亡与复活。
- `Combat`：武器基类、弹药、换弹、射线/散射命中、伤害结算。
- `Inventory`：格子背包、自动拾取、掉落物、物品堆叠。
- `BaseSystem`：保护罩、共享箱、入侵检测、报警。
- `Loot`：刷新点、权重表、品质和建筑区域刷新。
- `AI`：感知、目标评分、状态机、NavMesh 移动、战斗。
- `Networking`：登录、Session、Relay、房间、队伍分配、网络生成。
- `UI`：主菜单、房间、HUD、背包、共享箱、结算。
- `DebugTools`：快速阶段、无敌、传送、刷物资、模拟延迟、日志面板。

## 5. 各部门怎么做

本项目以“一人多岗位 + AI 辅助”执行，每个部门都必须产出可检查的交付物。

### 5.1 制作人 / 项目管理

职责：锁范围、排优先级、维护风险和每日构建，避免功能膨胀。

交付物：

- 每周里程碑和 P0/P1/P2 Backlog。
- 每个功能的完成定义：代码完成、联机验证、UI 提示、异常处理、构建验证。
- 每周一次可执行 Build，不以编辑器内可运行为完成。
- Bug 分级：崩溃/无法结算为 S0，规则或联机错误为 S1，体验问题为 S2，美术问题为 S3。

AI 协作：拆任务、生成验收清单、整理变更记录、分析日志；最终范围决策由制作人确认。

### 5.2 游戏策划

职责：把当前策划案转为可实现、可测试的数据表和状态规则。

交付物：

- 三阶段状态转换表和所有边界情况。
- 武器、护甲、医疗、背包容量和刷新权重表。
- 地图热区、出生区、建筑、物资点、进攻路线布置图。
- AI 行为优先级和难度参数。
- 3 分钟快测配置与 12 分钟正式配置。

首轮重点验证：

- 3 分钟发育是否过长或过短。
- 共享箱收益是否足以让玩家主动回家存物资。
- 第二阶段偷家是否有反制空间。
- 决战阶段是否会出现长期躲藏导致平局。

AI 协作：生成边界用例、模拟数值表和测试局记录总结；不允许 AI 自行编造玩家测试结论。

### 5.3 客户端 / Gameplay 程序

职责：完成玩家操作、战斗、物资、背包、共享箱、阶段与结算。

实现顺序：

1. 玩家移动、相机和训练场。
2. 武器、伤害、护甲、死亡与复活。
3. 物资刷新、拾取、背包、掉落。
4. 共享箱、保护罩、基地入侵。
5. 三阶段状态机和胜负结算。
6. 移动端输入和性能优化。

AI 协作：生成小模块脚手架、单元测试、Editor 工具和调试命令；每次合入前人工检查网络权限、生命周期和 GC 分配。

### 5.4 联机 / 后端

职责：保证 2V2 在公网环境中可以创建、加入并完整结算。

交付物：

- 匿名登录、创建 Session、加入码加入、退出和返回主菜单。
- 网络玩家生成、阵营分配、准备状态。
- 网络化伤害、掉落、背包、共享箱、阶段和 AI。
- 100～150ms 延迟、2% 丢包条件下的基本可玩性测试。
- 房主退出时明确提示并结束房间；首版不做主机迁移。

原则：第一周就完成“两台客户端移动和射击”的联机技术验证，不把联网留到玩法完成后再改造。

### 5.5 AI 程序

职责：让 Bot 能参与核心循环，而不只是站桩射击。

首版状态机：

`出生 → 搜索物资 → 拾取 → 背包评估 → 回基地存储 → 巡逻/跟队 → 发现敌人 → 战斗 → 治疗/撤退 → 复活或出局`

阶段差异：

- 阶段 1：搜物资优先，受击后反击，不主动冲基地。
- 阶段 2：按队伍角色在防守、搜集、突袭之间切换。
- 阶段 3：存活与抱团优先，血量低时治疗或撤退。

首版不做机器学习。使用可解释的有限状态机 + 目标评分，更容易调试，也适合面试展示。

### 5.6 关卡设计

职责：做出一个适合 2V2、可读性强的对称城镇。

灰盒布局：

- 红蓝基地位于地图两端，结构对称。
- 中路为高风险高价值物资区。
- 左右各一条侧路，分别偏室内和偏掩体外场。
- 每方基地至少两条可进入路线，避免唯一门口被完全封锁。
- 从基地到中路约 12～18 秒，从中路到敌方基地约 15～20 秒。
- 建筑内避免死胡同过多，门口具有高亮与阵营可读性。

关卡先用 ProBuilder/基础几何体验证动线，玩法通过后再替换低模资产。

### 5.7 角色与环境美术

职责：建立统一、可控、低成本的卡通低模风格。

交付物：

- 1 套 2 头身角色模型，红蓝材质换色。
- 基础动画：待机、八向移动、跳跃、下蹲、持枪、换弹、受击、粒子消散。
- 1 套模块化城镇：墙、地板、屋顶、门、窗、台阶、掩体、路面和装饰。
- 4 把高辨识度卡通武器、医疗包、护甲、弹药和共享箱。
- 材质图集和统一色板，减少材质数量与 Draw Call。

AI 协作：用于情绪板、配色和造型草图；最终游戏资产需自行重建或确认可商用授权，并保存来源和修改记录。

### 5.8 技术美术 / VFX

职责：保证风格统一、反馈清晰，并控制移动端开销。

交付物：

- 半透明保护罩呼吸材质。
- 枪口、命中、护甲破裂、治疗、掉落、箱子报警和淘汰粒子。
- 阶段切换全屏淡光，不使用强闪烁。
- 红蓝阵营材质规范、远距离轮廓和 LOD。
- 移动端粒子数量、透明层级和阴影开销预算。

### 5.9 UI / UX

职责：让玩家不用阅读长说明也能理解当前阶段和风险。

必要界面：

- 主菜单：单机训练、创建房间、加入房间、设置、退出。
- 房间：队伍、玩家/Bot、准备、加入码。
- HUD：阶段、倒计时、生命、护甲、武器、弹药、背包、两条命、队友状态。
- 交互：拾取提示、背包满、箱子存取、基地入侵、箱子被抢。
- 结算：胜利/失败/平局、击杀、死亡、拾取、存入、抢夺统计。

移动端要求：主要按钮位于拇指热区，战斗 HUD 不遮挡中央瞄准区域，背包和共享箱使用大点击目标。

### 5.10 音频

职责：以少量声音建立关键状态反馈。

首版音频清单：

- 4 类武器射击与换弹。
- 命中、护甲受击、空弹匣、拾取、治疗、存入、抢夺。
- 保护罩消失、终局开启、基地入侵、队友出局、胜负结算。
- 主菜单和战斗各 1 条循环音乐，终局增加节奏层。

所有外部音频保留许可证和来源链接。

### 5.11 QA / 数据验证

职责：验证规则正确、联机稳定、构建可运行。

测试矩阵：

- 单机：1 人 + 3 AI，连续 5 局无卡死。
- 联机：同机多开、局域网/公网两台设备、房主和客户端分别测试。
- 阶段边界：02:59、03:00、04:59、05:00、11:59、12:00。
- 死亡边界：阶段切换同时死亡、复活倒计时跨阶段、最终两人同时死亡。
- 物资边界：背包满、箱子满、抢夺中被杀、掉落后重复拾取、断线时持有物品。
- 性能：Windows 1080p 稳定 60 FPS；Android 中档设备 720p 目标稳定 30 FPS。

### 5.12 作品集包装

交付物：

- 90～120 秒演示视频：核心循环、联机、AI、共享箱偷家、终局决战、技术调试画面。
- 6～10 张高质量截图。
- 一页项目介绍：目标、职责、技术栈、难点、解决方案、结果。
- 一张架构图、一张三阶段流程图、一张 AI 状态机图。
- Git 提交历史和可读 README；敏感密钥、Library 与缓存不入库。
- 简历项目描述，突出本人实际完成内容，不写未落地功能。

## 6. 八周开发进度

### 第 0 周：预制作与环境（2026-11-02 ～ 2026-11-04）

目标：锁定首版范围，项目能稳定打开和提交。

- 新建 Unity 6 URP 项目。
- 建立 Git、`.gitignore`、目录规范、场景规范和命名规范。
- 安装 Input System、Netcode for GameObjects、Multiplayer Services、NavMesh 等必要包。
- 建立 `Bootstrap`、`MainMenu`、`TestGym`、`ArenaTown` 场景。
- 完成规则状态图、粗略地图草图和第一版 Backlog。

验收：空项目无报错；Windows 空包可构建；Git 可恢复；无关缓存不入库。

### 第 1 周：联机与战斗技术验证（2026-11-05 ～ 2026-11-11）

目标：两台客户端能在灰盒房间内移动、瞄准、射击、受伤和复活。

- 第三人称控制器和相机。
- 手枪射击、弹药、换弹、生命和伤害。
- Host/Client 创建与加入最小链路。
- 网络玩家生成、阵营颜色、基础位置同步。
- 主机权威伤害和第一版死亡/复活。

里程碑 M1：两人联机 10 分钟，无崩溃、无重复生成、双方伤害一致。

### 第 2 周：核心物资循环（2026-11-12 ～ 2026-11-18）

目标：完成“搜—捡—存—取—掉落—抢夺”。

- 4 类武器数据结构和基础手感。
- 子弹、医疗包、护甲。
- 固定格背包、自动拾取、满包提示。
- 死亡掉落和网络物品所有权。
- 共享箱存取界面、敌方只取不可存。
- 第一版物资刷新点和权重。

里程碑 M2：两名玩家可围绕共享箱进行完整物资争夺，状态在主机和客户端一致。

### 第 3 周：三阶段与完整结算（2026-11-19 ～ 2026-11-25）

目标：完整打通 12 分钟比赛。

- 三阶段网络状态机和同步时钟。
- 阶段 1 保护罩、立即复活。
- 阶段 2 保护罩移除、5 秒复活、基地入侵。
- 阶段 3 两条命、永久出局、阵营淘汰。
- 12 分钟平局和结算页面。
- 开发快测配置、阶段跳转和日志工具。

里程碑 M3：不使用手工干预即可从开局走到胜/负/平结算。

### 第 4 周：AI 与单机模式（2026-11-26 ～ 2026-12-02）

目标：玩家可以独自完成一局，AI 会参与物资与基地循环。

- NavMesh 和基础感知。
- 搜物资、拾取、存箱、跟队、战斗、治疗、撤退。
- 阶段驱动的目标权重。
- AI 补位和队伍平衡。
- 防卡死、重新寻路、无目标回退策略。

里程碑 M4：1 人 + 3 AI 连续完成 3 局，无站死、无无法结算。

### 第 5 周：关卡、美术与 UI 垂直切片（2026-12-03 ～ 2026-12-09）

目标：从灰盒变为可对外展示的第一版画面。

- 完成对称城镇动线和模块化低模替换。
- 角色红蓝换色、基础动画、武器与物资模型。
- 主菜单、房间、HUD、背包、共享箱、结算界面。
- 保护罩、阶段提示、命中、治疗、淘汰和入侵特效。
- 第一轮音效。

里程碑 M5：陌生测试者能够在不口头讲解的情况下进入游戏并理解主要目标。

### 第 6 周：公网联机与移动端（2026-12-10 ～ 2026-12-16）

目标：远程两人可用加入码开局，Android 能操作和完整结算。

- Sessions + Relay 正式接入。
- 房间异常、超时、退出和房主离开提示。
- 触控双摇杆、移动端瞄准与辅助瞄准。
- Android 构建、分辨率和 UI 安全区适配。
- 网络延迟、丢包测试和带宽检查。

里程碑 M6：两地网络完成一局；Android 真机完成一局；无 S0/S1 阻塞问题。

### 第 7 周：平衡、性能与稳定性（2026-12-17 ～ 2026-12-23）

目标：从“功能完成”提升到“稳定可展示”。

- 至少 10 局结构化测试，记录物资、击杀、阶段时长和胜负原因。
- 调整武器 TTK、刷新率、背包容量、建筑动线和 AI 权重。
- Profiler 定位 CPU、GPU、GC、网络带宽和峰值对象数量。
- 对象池、材质合批、粒子与阴影降级、音频压缩。
- 修复 S0/S1，清理明显 S2。

里程碑 M7：连续 5 局无崩溃、无软锁、无错误结算；Windows/Android 达到性能目标。

### 第 8 周：作品集交付与缓冲（2026-12-24 ～ 2026-12-30）

目标：形成可发送、可安装、可讲解的作品集包。

- 最终 Build、版本号、设置页和操作说明。

最终门禁：安装包在干净设备可启动；视频内容均来自真实可运行功能；文档描述与本人实际工作一致。

## 7. 每周工作节奏

- 周一：确定本周唯一里程碑，拆成不超过半天的任务。
- 周二至周四：开发，每完成一个纵向功能即做 Host/Client 验证。
- 周五：打包、测试、修复阻塞问题。
- 周六：邀请 1～2 人试玩并记录，不现场解释规则。
- 周日：复盘数据、更新 Backlog、冻结下周范围。

每天结束必须留下：可编译提交、当日变更说明、已知问题、下一步入口。

## 8. 首版验收标准

### 玩法

- 单机和 2V2 房间都能完成三阶段并正确结算。
- 阶段切换、保护罩、复活冷却、两命淘汰均无规则冲突。
- 共享箱支持己方存取、敌方只取，入侵与抢夺提示正确。
- 4 类武器、三类物资、背包与掉落形成可感知的策略差异。

### 联机

- 远程玩家可通过加入码进入同一房间。
- 伤害、生命、物资、箱子、阶段和胜负在所有客户端一致。
- 100ms 延迟下无明显重复拾取、重复伤害和角色瞬移失控。
- 房主退出不会让客户端无限等待。

### AI

- AI 能搜索、存储、战斗、治疗、复活和出局。
- AI 不会长时间卡墙、原地抖动或持有目标失效后停机。
- 单机连续 5 局均可自动走到结算。

### 表现与性能

- 红蓝阵营、基地、保护罩、共享箱和物资远距离可辨认。
- 关键事件同时具有视觉、声音和文字反馈。
- Windows 1080p 目标 60 FPS；Android 中档设备 720p 目标稳定 30 FPS。
- 最终 Build 无红色日志、无崩溃、无流程软锁。

## 9. 风险与对策

| 风险 | 概率/影响 | 对策 |
|---|---|---|
| 联机后补导致大规模返工 | 高/高 | 第 1 周先做网络技术验证，所有核心状态按权威模型设计 |
| AI 目标过多无法完成 | 中/高 | 先完成搜集、存箱、战斗三状态，再逐步增加撤退和突袭 |
| 低模美术耗时超标 | 高/中 | 模块化场景、同模换色、先统一色板和轮廓，不追求资产数量 |
| WPS 云盘锁定或同步 Unity 文件 | 中/高 | Git 为主版本管理；排除 Library、Temp、Logs、obj、Build 缓存；出现锁文件立即将 Unity 工程移到本地非同步目录 |
| 移动端性能不足 | 中/高 | 第 3 周开始真机冒烟测试，不等美术全部完成；限制透明、实时阴影和粒子 |
| 规则多但玩家看不懂 | 中/高 | 每个阶段只显示一个主目标，用颜色、声音和倒计时重复强化 |
| 功能膨胀 | 高/高 | P1 不得阻塞 P0；新想法进入后续列表，不插入当前周里程碑 |
| AI 生成代码不可维护 | 中/中 | 小步生成、人工审查、先测试后合并，禁止一次生成整套核心架构 |
